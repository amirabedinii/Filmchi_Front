# استراتژی تست و مستند تست

**English:** [Testing Strategy & Test Documentation](Testing.md)

---

این سند **استراتژی تست** و **موجودی تست** فرانت‌اند Filmchi را شرح می‌دهد.

---

## ۱. پشته و راه‌اندازی

پروژه از **Vitest** با **React Testing Library** و **jsdom** برای تست واحد و کامپوننت استفاده می‌کند.

- **اجراگر تست:** Vitest (`vitest` در `package.json`).
- **فایل راه‌اندازی:** `vitest.setup.ts` — Vitest را با مچرهای `@testing-library/jest-dom` گسترش می‌دهد، بعد از هر تست `cleanup()` اجرا می‌کند و یک polyfill برای `window.matchMedia` در jsdom تعریف می‌کند.
- **محل تست‌ها:** `src/__tests__/` — همهٔ فایل‌های تست اینجا قرار دارند (مثلاً `auth.test.tsx`, `routing.test.tsx`).

---

## ۲. دستورات تست (`package.json`)

| دستور | منظور |
|------:|------:|
| `npm run test` یا `yarn test` | اجرای تست‌ها (Vitest). |
| `npm run test:ui` یا `yarn test:ui` | باز کردن Vitest UI (تعاملی). |

در `package.json` پیش‌فرض اسکریپت جداگانهٔ `test:cov` وجود ندارد؛ در صورت نیاز می‌توان با `vitest run --coverage` اضافه کرد.

## ۴. شیوه‌های تست

- **Mock کردن:** سرویس‌ها (مثلاً `@/services/auth`, `@/services/movies`) با `vi.mock()` mock می‌شوند تا تست‌ها API واقعی را صدا نزنند. استورها را می‌توان mock یا ریست کرد (مثلاً `useAuthStore.getState().logout()` در `beforeEach`).
- **مسیریابی:** از `createMemoryRouter` در `react-router-dom` با همان درخت مسیر اپ (یا زیرمجموعه) و `initialEntries` برای شبیه‌سازی ناوبری استفاده می‌شود.
- **Providerها:** تست‌ها اپ (یا صفحه) را در `QueryClientProvider` (TanStack Query) و اغلب `RouterProvider` می‌پیچانند؛ تست‌های احراز هویت در صورت نیاز از `Toaster` هم استفاده می‌کنند.
- **i18n:** تست‌هایی که فارسی/RTL را بررسی می‌کنند از نمونهٔ واقعی i18n استفاده می‌کنند؛ بقیه ممکن است mock کنند یا به زبان پیش‌فرض تکیه کنند.
- **دسترسی‌پذیری / کوئری‌ها:** ترجیح با `getByRole`, `getByLabelText` و `findBy*` برای محتوای async؛ تست‌ها با regex هم برچسب انگلیسی و هم فارسی را پشتیبانی می‌کنند (مثلاً `/Login|ورود/i`).

---

## ۵. شکاف‌ها و پیشنهادها

- **گزارش پوشش:** اضافه کردن اسکریپت `test:cov` (مثلاً `vitest run --coverage`) و اختیاراً اعمال حداقل پوشش در CI.
- **E2E:** در راه‌اندازی فعلی به Playwright/Cypress E2E اشاره‌ای نیست؛ برای جریان‌های بحرانی کاربر (ورود → خانه → جستجو → جزئیات فیلم) اضافه کردن E2E پیشنهاد می‌شود.
- **کلاینت API:** نمونه axios و اینترسپتورها (رفرش توکن، retry) به‌صورت واحد مستقیم تست نشده‌اند؛ به‌طور غیرمستقیم از طریق تست‌های احراز و صفحه پوشش داده می‌شوند. در صورت پیچیده شدن رفتار، جداسازی اینترسپتورها برای تست واحد پیشنهاد می‌شود.

---

## ۶. CI

پروژه شامل `.github/workflows/ci.yml` است؛ مطمئن شوید job مربوط به CI دستور `yarn test` (یا `npm run test`) را اجرا می‌کند تا همهٔ تست‌های `src/__tests__/` در هر push/PR اجرا شوند.

---

با اضافه شدن فیچر یا صفحهٔ جدید، موجودی تست بالا را گسترش دهید و فایل تست مربوطه را در `src/__tests__/` اضافه یا به‌روز کنید.
